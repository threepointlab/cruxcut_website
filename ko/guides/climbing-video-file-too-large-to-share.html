파일 용량 문제 해결

클라이밍 영상 용량이 너무 커서 공유가 안 될 때: 작은 사본 만들기

클라이밍 원본 영상은 그대로 두고 공유용 작은 사본을 만드세요. 파일 용량 제한을 확인하고, 필요 없는 구간을 자르고, 보내기 전에 내보내기 화질을 비교해요.

2026년 11월 9일 게시 · CruxCut 팀

원본은 지키고, 공유 문제만 해결하세요

등반 시도는 잘 찍었는데 메시지나 업로드가 파일을 받아 주지 않아요. 설정을 전부 낮추기 전에 실제로 무엇이 실패했는지부터 확인하세요. 파일 용량 제한, 느린 인터넷 연결, 지원하지 않는 형식, 재생되지 않는 클립은 각각 다른 문제예요. 파일을 줄이는 건 용량이 걸림돌일 때만 의미가 있어요.

이 가이드는 전달용 사본을 따로 만드는 실전 워크플로예요. CruxCut에 목표 파일 용량을 정하는 기능이 있다거나, 하나의 내보내기 설정이 모든 곳에 통한다고 말하는 것은 아니에요. 편집본과 실제로 전달된 결과를 모두 확인할 때까지 손대지 않은 원본은 남겨 두세요.

다시 내보내기 전에 오류 메시지를 읽으세요

  • 용량 제한이 명시된 경우: 보내려는 곳의 현재 제한과, 그 제한이 파일 하나 기준인지 메시지 전체 기준인지 확인하세요. 다른 서비스에서 기억해 둔 제한 말고, 해당 서비스의 도움말 페이지를 직접 확인하세요.
  • 업로드가 멈추는 경우: 인터넷 연결과 서비스에서 중단을 알리는지 확인하세요. 전송이 멈췄다고 해서 영상이 용량 제한을 넘었다는 증거는 아니에요.
  • 지원하지 않는 파일이거나 재생 오류인 경우: 파일 형식과 보내려는 곳에서 지원하는 형식을 확인하세요. 지원하지 않는 형식 그대로라면 크기를 줄여도 실패할 수 있어요.
  • 기기 저장 공간이 부족한 경우: 공유 제한이 아니라 기기 용량 문제일 수 있어요. 확인되지 않은 내보내기 파일을 위해 하나뿐인 원본을 지우지 마세요.

저장된 파일의 정보 화면에서 확인할 수 있다면 용량, 길이, 해상도, 형식을 적어 두세요. 영상 길이(초)만으로는 몇 MB인지 알 수 없어요. 길이가 같은 두 클립도 용량은 크게 다를 수 있어요.

받는 사람이 봐야 할 것을 고르세요

발 기술을 봐 주는 코치와 성공한 무브 하나를 보려는 친구에게 필요한 영상은 달라요. 베타 리뷰용이라면 무브로 들어가는 과정, 손발이 홀드에 닿는 모습, 결과를 알 수 있을 만큼의 마무리를 남기세요. 짧은 SNS용 클립이라면 관계없는 대기 시간은 빼되, 시도가 실제와 다르게 보이지 않게 하세요.

자르기 구간 체크리스트부터 시작하세요. 카메라 쪽으로 걸어오는 장면, 벽만 오래 비치는 구간, 관계없는 시도는 이 사본의 목적에 필요하지 않을 때만 자르세요. 짧은 버전에서 준비 동작이 안 보인다면 더 긴 리뷰용 버전을 따로 남겨 두세요.

세션 전체를 내보내기 전에 짧게 테스트하세요

  1. 원본을 복제하거나 그대로 보관하세요. 전달용 사본에는 session-problem-attempt-share처럼 알아보기 쉬운 이름을 붙이세요.
  2. 가능하면 빠른 무브, 작은 풋홀드, 완등 장면이 들어간 대표 구간을 고르세요.
  3. 편집 앱이 지원하는 평소 설정으로 한 번 내보내세요. 결과 용량과 실제로 쓴 설정을 기록하세요.
  4. 그래도 너무 크다면 지원되는 설정을 한 번에 하나씩 바꾸고 저장된 결과를 비교하세요.

짧은 샘플로 테스트하면 긴 세션을 내보내느라 시간을 쓰기 전에 홀드 모서리가 뭉개지거나 프레임이 빠지는 문제를 미리 알 수 있어요. 다만 이건 화질 테스트일 뿐, 더 긴 클립이 보내려는 곳의 제한에 맞는다는 보장은 아니에요. 최종 전체 길이 파일은 따로 확인하세요.

있지도 않은 프리셋 말고, 실제 있는 설정을 쓰세요

편집 앱에서 출력 해상도를 낮추거나 화질/비트레이트를 조절할 수 있다면, 사본에서 조금만 낮춰 보세요. 설정 항목은 앱마다 다르니 쓰는 앱에서 직접 확인하세요. “HD”나 “고화질” 같은 이름이 두 편집 앱에서 같은 해상도나 같은 파일 용량을 뜻한다고 가정하지 마세요.

비트레이트를 낮추면 같은 길이에서 용량이 작아지는 경우가 많지만, 쓸모 있는 디테일까지 사라질 수 있어요. 컨테이너 이름 자체는 용량 설정이 아니에요. 파일 확장자를 직접 바꾼다고 영상이 변환되지는 않고, 오히려 파일을 열기 어려워질 수 있어요.

용량을 줄이려고 무작정 프레임률을 낮추지 마세요. 빠른 발 조정이나 다이내믹한 무브를 확인해야 한다면, 새로 저장한 클립에서도 그 동작이 잘 보이는지 비교하세요. 재생 속도와 프레임률은 따로 확인해야 해요. 결과의 속도가 바뀌었다면 슬로 모션·재생 속도 가이드를 참고하세요.

대략적인 용량 계산과 그 한계

도구에서 비트레이트를 직접 고를 수 있다면, 대략 이런 관계가 성립해요: 파일 바이트 ≈ 초당 전체 비트 수 × 길이(초) ÷ 8. 전체 비트레이트에는 영상뿐 아니라 오디오도 포함되고, 컨테이너가 약간의 오버헤드를 더해요. 예를 들어 전체 초당 8메가비트로 30초면 오버헤드를 빼고 십진 단위로 약 30메가바이트예요. 이건 단순 계산일 뿐, 클라이밍 영상에 권장하는 프리셋이 아니에요.

가변 비트레이트, 오디오 설정, MB/MiB 표기 차이 때문에 실제 저장 용량은 달라질 수 있어요. 엄격한 제한이 있다면 여유를 두고, 계산값을 약속처럼 믿기보다 최종 파일을 직접 확인하세요. 편집 앱에서 비트레이트를 보여 주지 않는다면 숨겨진 값을 추측하지 말고 실제 저장한 사본끼리 비교하세요.

보내기 전에 동작 디테일을 확인하세요

  • 원본과 작은 사본의 같은 순간을 일반 재생 속도로 보세요.
  • 특히 빠른 동작과 벽의 어두운 부분에서 손과 암벽화가 홀드와 어떻게 맞닿는지 확인하세요.
  • 시작과 끝이 여전히 들어 있는지, 소리를 살리려 했다면 소리가 있는지 확인하세요.
  • 저장한 사본을 편집 앱 밖에서 열어 보세요. 편집 앱 미리보기는 실제 전달되는 파일이 아니에요.

크롭을 더 타이트하게 하면 용량이 공짜로 줄어든다고 생각하지 마세요. 출력 해상도와 인코딩에 따라 용량이 줄지 않을 수 있고, 원본의 작은 부분을 확대하면 디테일을 알아보기 더 어려워질 수 있어요. 구도는 세로 크롭 가이드로 따로 확인하세요.

한 번 더 압축하기보다 링크가 나을 때

받는 사람이 자세히 분석하려고 원본이 필요하다면, 이미 믿고 쓰는 파일 공유 서비스를 고려해 보세요. 단, 그 서비스의 제한과 접근 권한 설정을 따라야 해요. 받는 사람이 의도한 파일에 접근할 수 있는지, 링크가 비공개 폴더 전체를 노출하지 않는지 확인하세요. 링크는 전달 방식을 바꿀 뿐, 내려받은 파일이 원본 화질이라는 것을 보장하지는 않아요.

알아볼 수 있는 주변 사람이나 사적인 대화가 담겼다면 공유 전에 먼저 물어보세요. 가능하면 받는 사람만 볼 수 있는 링크를 쓰고, 링크가 있는 사람만 볼 수 있다고 해서 비공개라고 가정하지 말고 실제 권한을 확인하세요. 메시지 첨부 용량 제한을 피하려고 공개 링크를 만들지는 마세요.

전달된 사본을 한 번 확인하세요

기기에 저장된 사본이 확인을 통과한 뒤에 보내거나 업로드하세요. 그다음 올린 곳에서 처리된 결과를 확인하거나 받는 사람에게 재생되는지 물어보세요. 저장한 사본은 잘 보이는데 전달된 사본이 그렇지 않다면 공유 화질 가이드를 따르세요. 업로드 후 서비스가 처리하는 과정은 다시 내보내기를 반복해도 해결되지 않을 수 있어요.

원본, 선택한 전달용 사본, 그리고 그 사본의 용도를 적은 짧은 메모를 함께 남겨 두세요. 목표는 가능한 한 작은 파일이 아니라 받는 사람이 열어서 쓸 수 있는 파일이에요. 이 워크플로는 특정 플랫폼의 현재 업로드 제한, 보장된 압축률, CruxCut의 내보내기 기능을 확인해 주는 것이 아니에요.
